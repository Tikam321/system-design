# N+1 Query Problem

## What is N+1 Query?

The **N+1 Query Problem** occurs when Hibernate executes:
- **1 query** to fetch the parent entities.
- **N additional queries** to fetch the child entities lazily.

### Example

```java
List<User> users = userRepository.findAll();

for (User user : users) {
    System.out.println(user.getOrders().size());
}
```

### Queries Executed

```sql
SELECT * FROM users;                  -- 1 query

SELECT * FROM orders WHERE user_id=1;
SELECT * FROM orders WHERE user_id=2;
SELECT * FROM orders WHERE user_id=3;
...
```

If there are **100 users**, Hibernate executes:

```
1 + 100 = 101 Queries
```

This results in unnecessary database calls and poor performance.

---

# How to Avoid N+1 Query?

## ✅ Solution 1: JOIN FETCH (Most Common)

```java
@Query("""
SELECT DISTINCT u
FROM User u
JOIN FETCH u.orders
""")
List<User> findAllUsersWithOrders();
```

Generated SQL:

```sql
SELECT *
FROM users u
JOIN orders o
ON u.id = o.user_id;
```

Now Hibernate fetches **Users and Orders in a single query**, eliminating the N+1 problem.

---

## Other Solutions

- **`JOIN FETCH`** (Most commonly used)
- **`@EntityGraph`**
- **Batch Fetching (`@BatchSize`)**
- **DTO Projection** (fetch only required fields)

---

## Interview Answer

> **The N+1 Query Problem occurs when Hibernate first loads parent entities using one query and then executes one additional query per parent entity to lazily load its child entities. It increases database round trips and degrades performance. We can avoid it using `JOIN FETCH`, `@EntityGraph`, batch fetching, or DTO projections to fetch the required data efficiently.**
